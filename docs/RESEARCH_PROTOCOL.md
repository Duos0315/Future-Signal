# Research integrity and experiment record protocol

## 1. Evidence classes

Use explicit labels and never silently promote one class into another:

- **Synthetic model output:** generated by a documented toy or simulation model.
- **Measured observation:** data collected by an identified source, with units, time and geographic coverage.
- **Derived indicator:** a calculation over identified observations with a documented formula.
- **Hypothesis:** a proposed explanation or question that has not been established.
- **Human-reviewed source:** a reference inspected by a reviewer; this does not automatically validate every claim.
- **Validated finding:** a narrowly scoped result that passed a documented validation protocol and independent review.

A URL submitted by a user is a reference, not proof. A source may support, challenge or contextualize a claim; that relationship must be justified.

## 2. Minimum experiment metadata

Every shareable or publishable experiment record should include:

- Stable experiment ID.
- Created timestamp in ISO 8601 UTC.
- Signal/question ID, if applicable.
- Model name and semantic version.
- Model family and explicit model scope.
- Seed and trial count.
- Requested inputs and effective normalized parameters.
- Units and parameter bounds.
- Output metrics with definitions.
- Assumptions and known limitations.
- Data/source references and retrieval timestamps, if any.
- Software/repository revision.
- Validation status and reviewer history.

Do not store secrets or sensitive personal data in public experiment records.

## 3. Comparison protocol

- Define the primary outcome before running a comparison.
- Keep baseline and intervention settings explicit.
- Use reproducible seeds and disclose whether random streams are truly paired.
- Report absolute outcomes as well as deltas.
- Report improved, tied and declined trial counts.
- Do not call a mean difference statistically significant without an appropriate inferential procedure.
- Add uncertainty intervals only when the sampling design and assumptions justify them.
- Change one parameter at a time for basic sensitivity checks; use a documented design for multi-parameter exploration.
- A simulation comparison is not proof of causal effect in a real system.

## 4. Real-world data provenance

For every external dataset record:
- Provider and dataset title.
- Canonical source URL and license/terms.
- Dataset version or release identifier.
- Retrieval time and source publication/update time.
- Geographic and temporal coverage.
- Units, transformations and aggregation rules.
- Missingness, quality flags and known biases.
- Any derived calculations and code revision.

Never silently fill missing values. If imputation is used, name the method and expose the imputed share.

## 5. Validation ladder

1. **Software verification:** tests confirm code behaves as specified.
2. **Internal model checks:** invariants, edge cases and sensitivity checks.
3. **Benchmark comparison:** known reference cases or independently computed results.
4. **Calibration:** parameter fitting against appropriate observations, with held-out data.
5. **External validation:** performance assessed on data not used for calibration.
6. **Independent review:** domain expert checks assumptions, scope and interpretation.

Passing an earlier level does not imply passing a later one.

## 6. Public language

Preferred:
- "The synthetic model produced..."
- "Under these assumptions..."
- "This dataset reports..."
- "The result is consistent with..."
- "The model has not been validated for this use."

Avoid:
- "The AI predicts..." when no validated predictive model exists.
- "Verified" when only a URL was checked.
- "Proven" based on one simulation.
- "100% accurate" without a defensible evaluation protocol.

## 7. Safety boundary

FUTURE//SIGNAL is an exploratory and educational system. Do not use toy simulations as the sole basis for medical, emergency, engineering, infrastructure, financial, legal or public-policy decisions. Real-world deployment requires domain expertise, appropriate data governance, independent validation and safety review.
