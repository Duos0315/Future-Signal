# FUTURE//SIGNAL — Product Vision

## North star
FUTURE//SIGNAL is an open, evolving digital universe for exploring possible futures through science questions, systems thinking, conceptual engineering and reproducible experiments.

It is not intended to be a news feed, a static collection of articles, a leaderboard, or a pretend autonomous AI civilization. Its central promise is to help people move from curiosity to a testable model, from a model to a design, and from a design to a traceable learning record.

## The complete discovery loop
1. **A world cycle creates a signal.** A deterministic daily engine combines domains into a question, a hypothesis prompt, variables, a method and explicit caveats.
2. **Specialist perspectives interrogate it.** Scout, Systems Architect, Skeptic and Builder roles surface unknowns, dependencies, falsification paths and test designs. These are transparent deterministic software roles, not independent LLM agents.
3. **A visitor builds a blueprint.** Conceptual modules describe a possible habitat, swarm, network, energy system or ecosystem. The blueprint is a structured design sketch, not CAD or a deployable engineering plan.
4. **The experiment engine tests a proxy.** Local models simulate network resilience, grid coverage or bounded-resource service. Each model exposes its assumptions and limits.
5. **Scenarios are compared.** Baseline and intervention runs use per-trial deterministic seeds. The interface reports score deltas and trial outcomes without pretending these are statistical proof.
6. **Evidence is attached.** Users can link sources to a signal and state whether each supports, challenges or contextualizes it. References remain unverified until a human reviews them.
7. **The community reviews proposals.** Issue Forms collect structured ideas. GitHub Actions labels and acknowledges submissions. Maintainers—not automation—decide whether an idea enters the generator or model code.
8. **The next cycle evolves the world.** The next dated signal changes the biome, anomaly and initial experiment modifier, while personal progress remains on the visitor's device.

## Product principles
- **Curiosity over certainty:** questions and hypotheses are not discoveries.
- **Transparency over mystique:** rules, seeds, assumptions and limitations are visible.
- **Experiments over engagement tricks:** no fake users, fake activity or meaningless public rankings.
- **Evidence over authority theatre:** references are labelled by type and verification status.
- **Human review over auto-publication:** community ideas are never silently promoted to science claims.
- **Accessible ownership:** export and import local progress; no account or paid API is required.
- **Honest scope:** local browser progress is not multiplayer; deterministic roles are not autonomous researchers; toy models are not real-world engineering validation.

## Current architecture
GitHub Pages hosts the static site. GitHub Actions runs daily generation, validation, regression tests and community intake triage. Versioned JSON files store the public signal and archive. Browser modules run the simulations and local universe. localStorage stores personal progression, with JSON backup/restore. GitHub Issues and pull requests provide the human-reviewed contribution path.

## Evolution path
- Richer world biomes, resource states and anomaly interactions.
- Blueprint connections, constraints, budgets and model adapters.
- Sensitivity analysis and counterfactual experiment design.
- Evidence metadata, review states and curated reference collections.
- Optional shared collaboration only if an appropriate backend and privacy model are deliberately adopted.

The project should grow by making the discovery loop deeper and more rigorous—not by pretending to have capabilities that its architecture does not support.
