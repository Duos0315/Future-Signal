# FUTURE//SIGNAL

**A living laboratory for strange ideas, science experiments and tomorrow's technology.**

FUTURE//SIGNAL is a static, open-source playground. A deterministic generator publishes a new science/engineering prompt every day. Visitors can explore the daily signal, browse a small archive and run a browser-based what-if toy model.

## Principles

- No external LLMs or inference APIs.
- No paid APIs, database, or always-on server.
- Static site hosted on GitHub Pages.
- Daily content generated by a small Node.js script in GitHub Actions.
- Interactive what-if model runs locally in the visitor's browser.
- Outputs are prompts and illustrative models, not scientific proof or engineering advice.

## Run locally

Any static file server works. For example:

```bash
python -m http.server 8000
```

Then open http://localhost:8000.

Generate a signal locally:

```bash
node scripts/generate.mjs
```

## Enable GitHub Pages

In the repository, open **Settings → Pages** and choose **Deploy from a branch**, branch **main**, folder **/(root)**. Save. GitHub will publish the site at:

https://duos0315.github.io/Future-Signal/

The daily workflow runs at 00:17 UTC (05:17 Pakistan Standard Time) and can also be started manually from **Actions → Generate daily signal → Run workflow**.

## Project map

- `index.html` — site structure
- `styles.css` — responsive visual system
- `app.js` — browser interactions and data loading
- `data/daily.json` — latest published signal
- `data/archive/index.json` — recent signal index
- `scripts/generate.mjs` — deterministic content generator
- `.github/workflows/daily-signal.yml` — scheduled publishing workflow

## Important limitations

The generator uses fixed templates and date-based deterministic selection. It is not an AI and does not independently discover scientific facts. The What-if Lab is a deliberately simple illustrative index, not a validated physical simulation. Treat each signal as a hypothesis starter: test assumptions, find primary sources and invite domain experts to review it.

## Contribute

Open a GitHub issue with:
- the scientific or engineering question;
- the system you want to explore;
- variables that should be changed;
- references or evidence, where available;
- limitations and safety considerations.

Ideas that involve real-world experiments must include appropriate safety review.
